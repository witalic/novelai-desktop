Generation widget — two structured zones

The station stops being a free-form pile of blocks. It splits into two zones — a Generation zone (output + Generate) and a Composition zone (a category rail + an ordered block list, like the reworked Library widget). Blocks are a tidy, drag-reorderable list with per-block edit · save-to-Library · delete and a polarity toggle; polarity is the green/red left border. The two zones take an adjustable ratio and an orientation (side-by-side or stacked, either order) — handy for landscape output.

Decisions (from your answers) baked in
  • One list, polarity = color + a per-block ＋/− toggle; the assembled positive/negative strings live in the meta footer (unchanged token counters).
  • Category rail filters (single-select, no tag filter) — a view aid only; every block still generates regardless of the filter.
  • Order = manual drag-reorder (the list order is the prompt-assembly order). Default new choice — say if you'd rather group by category.
  • Orientation + ratio: axis toggle (⇔ side-by-side / ⇕ stacked) + swap which zone leads, kept in the footer (a fixed spot that never shifts); the splitter sets the ratio. Covers left|right and top|bottom. ＋ New block lives only in the Library widget (more capable there).

Anatomy

1
Station header (trimmed)

Now just the essentials: title, subscription balance, and the Generate button with its Anlas cost — the header reads clean. Layout controls live in the footer instead.

2
Footer — orientation + ratio

The orientation control sits in the meta footer — a fixed spot that never shifts as the layout changes: ⇔ side-by-side · ⇕ stacked · ⇄ swap which zone leads. The splitter between the zones sets the ratio. All persist with the work (layout). Make the Generation zone wide/short for landscape output.

3
Generation zone

The Output slot: live preview while generating, the latest result (drag out to keep), the stack badge, and the empty hint. Exactly today's Output column, now its own zone.

4
Composition — rail + list

A category rail (single-select filter, no tag filter) + the ordered block list. Reads like the reworked Library widget, so the two feel like one system. The filter is a view aid — all blocks generate.

5
Block row

Drag handle (reorder = assembly order), category dot, name, and actions: ＋/− polarity toggle, ▸ expand to edit the prompt inline, ↥ save to Library, ✕ delete. Polarity is the green/red left border.

6
Meta footer

The assembled + / − prompts with live T5 token counts vs the model budget — the reproducible payload that gets sent. The orientation control is docked at its right (fixed, never moves).

Behavior rules

Composition = ordered listBlocks are a single drag-reorderable list, not free-placed nodes. List order = prompt-assembly order (was left-to-right x). Reordering within a filtered category preserves the global order of the rest.
PolarityPer-block, shown as the green (positive) / red (negative) left border + a ＋/− toggle. The meta footer assembles the two strings separately; token counts stay per-lane.
Rail filters, never excludesSelecting a category shows only its blocks in the list; All shows everything. It never removes a block from the composition — filtering is view-only, generation always uses the whole list.
Per-block actions▸ expand → inline prompt edit (this copy only). ↥ Save to Library (opens the editor drawer prefilled). ✕ delete from the composition. ＋/− flip polarity. Drag-out to the canvas still detaches a copy to scratch.
Adding blocks⇢ / drag from the Library widget lands a copy at the end of the list (strict polarity routing as today). New blocks are authored in the Library widget's ＋ New block (not duplicated here) and dropped in.
Orientation & ratioAxis (h/v), lead-zone (swap), and the split ratio persist with the work (layout layer, like today's outputRatio/posRatio).
Data-model changeStation blocks drop free xFrac/laneFrac and gain an order index; the station gains layout (axis, lead, ratio). Schema bump + migration (place old blocks by their x order, default axis = side-by-side).
