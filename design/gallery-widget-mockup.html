Structured gallery — a composable canvas widget

A new canvas node (beside the Prompt widget and the Station) that replaces free-placed image nodes with a structured, composable gallery of the current work's images. It's a vertical stack of blocks you arrange yourself — Section · Heading · Text · Image grid · Metadata · Divider — dragged to reorder. Image-grid blocks lay images into fixed cells with a source filter and column count, and scroll inside the block when there are many, so the node never grows unbounded.

Decisions baked in (from your answers) — confirm on review
  • A canvas node on Generate (like the other widgets), not a separate view. It organizes one work's gallery images.
  • Vertical block stack (single column, Notion-like): a grip appears on hover to drag-reorder; ＋ Add block in the header inserts a Section / Heading / Text / Image grid / Metadata / Divider.
  • Image-grid = fixed cells + internal scroll. Each grid has a source (All · Favorites · Tag · Group), a column count (2–4), and its own scroll — so blocks stay compact.
  • Sections are collapsible group boundaries — collapsing one hides the blocks under it until the next Section.
  • Data-model change: the work gains a gallery node holding an ordered block list; grid blocks store a query + columns, text/heading store their text, metadata stores field defs. Structured gallery replaces free placement for gallery-role images (scratch stays loose). Schema bump + migration — confirm the fork.

Anatomy

1
Node header (clean)

Just Gallery · <work> · N images and ＋ Add block — the essentials, matching the trimmed Station header. The whole node is a Vue-Flow node; collapse/resize behave like the others.

2
＋ Add block

A labelled menu (no cryptic glyphs): Section · Heading · Text · Image grid · Metadata · Divider. Inserts at the end (or after the focused block). Also available in the footer.

3
Block gutter

Every block gets a hover ⠿ grip (drag to reorder the stack) and a hover action cluster (⚙ settings where relevant, 🗑 delete). Idle, blocks read clean — controls appear on hover.

4
Section

A group boundary with a title, a live count, and optional summary chips. Its ▸ collapses everything under it until the next Section — so a long gallery folds down to its outline.

5
Image grid

The core block: images in fixed cells (uniform aspect, cover). A toolbar sets the source (All · Favorites · Tag · Group), the column count, and shows the count. Overflow scrolls inside the block, so the node stays compact. ★ favourite, click to preview, drag a thumb out to the canvas.

6
Metadata & Text

Metadata = a properties strip (Tags · Date · Model · Seed · Dimensions…), values pulled from the images/snapshot or typed; add/remove fields. Heading / Text are inline-editable copy for titles and notes.

Behavior rules

Layout = ordered blocksThe gallery is a single drag-reorderable list of typed blocks — not free-placed nodes. Order is the read order, top to bottom. Stored on the work's gallery node (layout layer).
Image gridRenders the work's gallery-role images into fixed cells. Source is a saved query (all · favorites · tag:<x> · group:<g>); columns 2–4; a max-height with internal scroll keeps the block compact. The same image can appear in several grids (grids are views, not folders).
SectionA boundary block. Collapsing hides every block after it up to the next Section (or the end). Count/summary chips reflect the grids inside it.
MetadataA properties block with add/removable fields. Auto values read from the images/snapshot (date range, model, seed, dimensions, tag union); free fields are typed. View-only or editable per field.
Image actions★ toggles favourite (persists on the image). Click opens the shared image preview. Drag a thumb out to the canvas detaches a loose (scratch) copy. Right-click keeps today's context menu (download, delete, arrange).
Adding blocks＋ Add block inserts by type. New Image grid defaults to source:all, 3 columns. Deleting a grid never deletes images (they live in the work); it only removes the view.
Data-model changeNew gallery node: { blocks: [{type, …}] }. Gallery-role images stop carrying a free position and are surfaced only through grid blocks; scratch images stay loose on the canvas. Schema bump + migration (seed one grid source:all from a work's existing gallery images).
