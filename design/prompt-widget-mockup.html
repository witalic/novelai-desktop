Prompt widget — quick access with a Library search mode

The Library anchor zone becomes a two-mode widget. Quick access holds the work’s hand-picked palette (plus on-the-fly custom blocks) and feeds the station; Find in Library searches the vault — pinned blocks leave its pool. Every ＋ / drag out of the palette produces an independent copy; the palette itself persists with the work.

Anatomy

Numbered against the callouts above (3–4 belong to Find-in-Library mode).
1
Zone header

Unchanged zone grammar: icon, title, anchor tag, collapse chevron. Collapse state persists with the work (layout layer, like the station ratios); scroll position doesn’t.

2
Mode switch

Quick access — the work’s palette (zone children, persisted). Find in Library — read-only vault search whose pool excludes already-pinned blocks. Mode + filters are transient; a reopened work starts in Quick access.

3
Search (browse)

Debounced name + text search via GET /library/blocks?search=. / focuses it. Pinned blocks that match the query appear greyed-out with a Pinned ✓ mark — search never pretends a block doesn’t exist; clicking one jumps to it in Quick access.

4
Category dropdown + tag filter (browse)

Categories moved from chips to a searchable dropdown — chips don’t scale past ~20 categories. Counts and category colors inside; tag typeahead unchanged (AND-semantics).

5
Palette list + hover card

In Quick access the category chips are derived from the pinned set and sorted by count — a naturally small, self-pruning filter row. The list ends with a full-width ＋ New custom block row (not in the chips row — it creates a block, not a filter). Hover ~250 ms opens the details card with Prompt and Gallery tags labelled apart, provenance, and the block’s actions (Save to Library / Update). Unpin is the ✕ on the row itself.

6
Footer

Count + “Open Library ↗” escape hatch. The widget writes to the vault only on the explicit Save to Library action — nothing else ever mutates Library blocks.

Behavior rules (all locked)

Exclusive membershipPinning moves a block out of the Find-in-Library pool: default listings exclude pinned blocks. The vault block itself is untouched — exclusion is a view filter over this work’s pins.
Search never liesA search query that matches a pinned block shows it greyed-out with Pinned ✓ (click = jump to it in Quick access); default listings without a query exclude pinned blocks entirely.
Prompt ≠ tagsTwo independent fields with different jobs. Prompt (text) is the generative payload — the frozen copy that gets assembled and sent to NovelAI. Tags are curation metadata on the block: they propagate to generated images through the snapshot components and power gallery filtering and examples. Widget search matches name + prompt; the tag filter matches tags only. The hover card labels them apart.
Palette semantics＋ (strict polarity routing — positive → Positive lane, negative → Negative) and drag-out both create an independent copy: fresh node id, frozen text. The pinned original stays; editing a copy never touches it, editing the pinned master never touches already-placed copies. Unpin = ✕ on row hover — the block leaves the palette and returns to the Library pool (the vault block is untouched).
Magnetic drop-inDragging any canvas block over the widget shows an insertion slot; on drop the node re-parents to the zone and auto-packs into the single-column order (index from drop y). No free placement inside the widget.
Custom on the flyThe ＋ New custom block row at the list end creates a work-local custom block (category custom, local badge, no block_id). It persists with the work but is not in the vault until the user explicitly hits Save to Library… on the hover card — which opens the Library editor drawer prefilled (adjust name/category/tags at the moment of saving), then links the pin via the returned block_id.
Version driftA pinned copy never auto-updates (freeze semantics). If the Library block moved on (pinned v2, vault at v4), the row and hover card show ↻ v4; updating is an explicit action that re-freezes the newer text.
PersistencePalette = zone children → persisted with the work (Phase-1 layout/domain split). Collapse state persists (layout). Mode, filters, search, scroll — transient.
Categories at scaleBrowse: searchable dropdown with counts (survives 20+ categories). Quick access: chips derived from pinned blocks, sorted by count desc — bounded by the palette itself.
DataExisting endpoints only (/library/blocks|categories|tags) + the LibraryView race guard; the single new write path is Save to Library → existing POST /library/blocks.
Design locked — decision log
  • Two modes: Quick access (persisted palette) / Find in Library (transient read-only search) · collapse persists, filters don’t.
  • Exclusive membership: pinning removes the block from the Library pool; search shows pinned matches greyed-out (Pinned ✓, click = jump).
  • ＋ / drag from the palette = independent copy (strict polarity routing on ＋); unpin = ✕ on row hover.
  • Custom blocks via the list-end ＋ New custom block row; graduate to the vault only through Save to Library… → prefilled Library editor drawer.
  • Version drift is explicit: pinned copies never auto-update; ↻ vN action re-freezes.
  • Categories: searchable dropdown in browse; count-sorted chips from the pinned set in Quick access.
  • Prompt (generative payload) and tags (curation metadata → image tags → gallery filters) are independent fields, labelled apart everywhere.
