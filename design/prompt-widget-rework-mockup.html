Prompt widget — direct Library browser with a left rail

The two-mode widget (Quick access palette + Find in Library) collapses into one direct browser over the whole Library, laid out like the full Library view: a category rail on the left (with a ★ Favorites view on top), a search + per-view tag pins in the header, and the blocks below. Favorites replace Quick access — a per-work star set. A block never lives in the widget; ★ favorites it, ⇢ / drag drops an independent copy into the work area, and ＋ New block spawns one there too.

Rev 3 — addressed from your review
  • ★ Favorites is now a toggle that composes with category navigation — it sits at the top of the rail and ANDs with the selected category (Body + ★ = favorited Body blocks; All + ★ = every favorite). It no longer replaces the category selection.
  • Polarity = the block’s left border color — green positive, red negative (+ faint red wash & NEG tag on negatives). Category is a dot before the name (the odd circle by the star is gone).
  • Tag search removed — the main search already matches tags. ★ and ⇢ always visible. Scrollbars themed (thin overlay thumbs, no reserved width) — matches the app’s global tokens.css.

Anatomy

Numbered against the callouts above.
1
Rail — ★ Favorites toggle

Top of the rail, above All blocks. A toggle, not a view: it stays lit while you also pick a category, and ANDs with it (Body + ★ = favorited Body blocks). Favorites persist with the work; they’re the replacement for Quick access.

2
Category rail (single-select)

The full Library’s left rail, compacted: All blocks + every category with its color dot and count, its own themed scroll for 20+ categories. Selecting one scopes everything to its right — the “current category”.

3
Search

Debounced, matches name + prompt + tags via GET /library/blocks?search=. / on the canvas focuses it. Combines with the rail view + tags (AND).

4
Tag pins (per view)

Tags for the current rail view, as multi-select chips (GET /library/tags?category=) in a self-scrolling area — a 40-tag category never blows out the header. AND-semantics. No separate tag search: the main search already matches tags.

5
Blocks + ＋ New block

First item is ＋ New block in «Category» — spawns a fresh block in the work area in the current category (All / Favorites → custom), ready to edit there. Each row: category dot, name, the polarity edge, and the two always-visible actions. Hover ~250 ms → details card.

6
Footer

Count of matches + Open in Library ↗, which carries the category + tag filters (opens the Library pre-filtered) but ignores Favorites — favorites are a work-local concept the shared Library doesn’t have.

Behavior rules

One poolNo modes, no palette. The list is always the whole Library narrowed by rail view → tags → search (all AND). Blocks never move “out of” the pool.
Favorites = quick accessThe ★ on a row toggles a per-work favorite (a Library block id kept on the WorkDoc). The rail’s ★ Favorites toggle filters to that set and ANDs with the selected category + tags + search. Nothing is copied — a favorite is a bookmark into the Library, persisted with the work.
Polarity legibilityLeft border color = polarity: green (--ok) positive, red (--danger) negative; negatives also get a faint red wash + a NEG tag. Category = a dot before the name (matches the rail). The two channels never collide.
Move to work area⇢ and drag-out both drop an independent copy into the station — strict polarity routing (positive → Positive lane, negative → Negative). Editing that copy never touches the Library block.
＋ New blockCreates a fresh block directly in the work area with the current rail category — or custom under All / Favorites — then focuses it for editing there. Custom blocks graduate to the vault via the Library editor’s Save to Library.
Actions always shownBoth row actions are always visible: ★ (filled = favorited, its state) and ⇢. No hover-reveal.
Footer linkOpen in Library ↗ hands the current category + selected tags to the Library view (deep-link filter); it drops the Favorites view — favorites don’t exist outside this work.
PersistenceFavorites + collapse persist with the work. Rail view, tags, search, scroll — transient (a reopened work starts at All / no filters).
DataExisting endpoints only: /library/blocks, /library/categories, /library/tags. New: a favorites: string[] field on the work recipe (schema bump + migration).
